# Empirical Bayes disproportionality analysis of FAERS drug-drug-event pairs

This repository contains an R script to estimate empirical Bayes geometric means (EBGM) for drug–drug–adverse event pairs using the `openEBGM` package. It was adapted to compare androgen receptor pathway inhibitor (ARPI)–cardiovascular medication combinations with the cardiovascular medication alone.

## Requirements

- R and the `openEBGM` package (`install.packages("openEBGM")`)
- A locally prepared CSV containing the columns `caseid`, `product`, and `outcome`

| Column | Meaning |
|---|---|
| `caseid` | Unique FAERS case identifier |
| `product` | Exposure label: ARPI–cardiovascular medication combination or cardiovascular medication alone |
| `outcome` | Cardiovascular outcome category or specific event label |

Each row must represent a **unique case–exposure–outcome triple**. Preprocessing, case deduplication, drug-name harmonization, creation of drug–drug pair labels, and eligibility restrictions must be completed upstream. Blank `outcome` values are converted to `none`, consistent with the supplied original analysis. Review whether this is appropriate for your source data.

## Cardiovascular outcome definitions

The input column is named **`outcome`**. The analysis recognizes labels supplied in the data, including:

- **Major adverse cardiovascular event (MACE)**: composite category comprising **Cardiovascular death**, **Nonfatal myocardial infarction**, and **Nonfatal stroke**.
- **Other cardiovascular event (OCE)**: composite category comprising **General cardiac disorders**, **Bleeding**, and **Thrombosis**.

## Comparison-specific datasets and outcome levels

**Each dataset evaluates one comparison:** an ARPI–cardiovascular medication combination versus the cardiovascular medication alone. For example, a prepared dataset may compare abiraterone plus ramipril with ramipril alone; another dataset may compare enzalutamide plus hydrochlorothiazide with hydrochlorothiazide alone. The `product` column contains labels for **both** the combination and its comparator. Different datasets are prepared according to the comparison of interest.

For each comparison, the same three columns (`caseid`, `product`, `outcome`) are used in **two separate outcome analyses**:

1. **Parent outcomes:** `outcome` is `Major adverse cardiovascular event` or `Other cardiovascular event`.
2. **Component outcomes:** `outcome` is `Cardiovascular death`, `Nonfatal myocardial infarction`, `Nonfatal stroke`, `General cardiac disorders`, `Bleeding`, or `Thrombosis`.

The script runs separately for each comparison and outcome level. It does **not** generate exposure groups, derive composite outcomes, or combine parent and component records. These steps are performed during upstream data preparation.

Illustrative parent-level input for a single comparison:

```csv
caseid,product,outcome
10001,abiraterone_ramipril,Major adverse cardiovascular event
10002,ramipril,Other cardiovascular event
```

Illustrative component-level input for the same comparison:

```csv
caseid,product,outcome
10001,abiraterone_ramipril,Cardiovascular death
10002,ramipril,General cardiac disorders
```

These are hypothetical records, not real FAERS cases. Use the exact product labels generated by your own preprocessing. A case may appear in multiple comparison datasets or in both outcome levels.

## Running the script

```bash
# Parent outcome analysis
Rscript ebgm_analysis.R input/abiraterone_ramipril_parent.csv output/abiraterone_ramipril_parent_ebgm.csv

# Separate component outcome analysis
Rscript ebgm_analysis.R input/abiraterone_ramipril_components.csv output/abiraterone_ramipril_components_ebgm.csv
```

Both inputs have the same schema but represent different outcome levels for the same drug comparison. Repeat the workflow with separate prepared files for each other ARPI–cardiovascular medication comparison. The script exports results for both the combination and the cardiovascular medication-alone labels present in each input.

The script fits a two-component gamma-mixture prior with multiple optimizer starting values, then calculates posterior mixture weights, EBGM, EB05, EB95, and the observed-to-expected ratio (`N/E`). The `EB05` and `EB95` values form a **90% posterior credibility interval**. The observed-to-expected ratio is **not** a reporting odds ratio (ROR).

## Interpretation and limitations

- This is a spontaneous-reporting disproportionality analysis, not an incidence or causal-risk analysis.
- Disproportionate reporting for a combination relative to a single-drug comparator does not establish a pharmacological interaction.
- A FAERS case may contribute to more than one comparison dataset when multiple products are reported.
- The analysis assumes the input dataset and its expected-count construction are appropriate for the scientific comparison. Inspect `processRaw()` documentation and verify results against your study protocol.
- The script does not independently calculate RORs, deduplicate FAERS versions, or control confounding.
